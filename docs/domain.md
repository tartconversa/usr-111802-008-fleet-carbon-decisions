# 配送车队运营业务数据

来源事件有来源编号、事件编号、修订、外部实体、发生时间和观察时间；同一来源同一事件的更高修订替代先前修订。主体映射只在来源与外部标识的组合内有效，无法映射的事件在现有摘要中列为未归属。通用金额是原始事件上的可选数值，不代表利润、节约额或结算结果。

报告发布接口保留报告正文和摘要哈希，相同编号不接受不同内容。业务口径、结论的适用范围和后续变化的影响需要与原始观察区分。

## 车辆分配历史

车辆到线路、动力类型的分配按区间保存：effective_from 是车辆实际换线的生效时间，recorded_at 是分配被登记进系统的时间。中途换线可能事后才补登（recorded_at 晚于 effective_from）；同一车辆同一生效时间的分配不允许内容冲突。查询某个发生时间点的有效分配时，可以用 as_of 限制只看见当时已登记的分配，这是按批准时点复现结论的前提。

## 行程与能耗事件口径

- trip：payload 的 service_units 是实际服务量（非负数值，缺省为 0 并计入缺服务量行程数）；empty:true 表示空驶，空驶行程不得同时登记正服务量。
- fuel：payload 的 liters 为正数；只有车辆当时分配为柴油时才计入，否则列为排除事件。
- charge：payload 的 kwh 为正数；只有车辆当时分配为电动时才计入。计费电量补录通过同一事件的更高修订或更晚观察的事件进入，只影响当前视图，不影响按时点的复现。

行程与能耗按发生时间找到车辆当时的线路分配，归属到对应线路。无法归属的事件（车辆未映射、该时段无线路分配、能耗类型与动力不符、数量无效、空驶与服务量矛盾）不参与计算，但在结果的 excluded_events 中逐条列明原因。

## 排放强度与改造比较

柴油排放 = 升数 × 柴油因子；电耗排放 = 电量 × 充电发生时刻所在时段的电力因子（分时段因子在 config/domain.json 配置，必须连续覆盖全天）。排放强度 = 归属排放 ÷ 实际服务量，每条线路分柴油侧与电动侧计算；空驶行程不产生服务量，其间的能耗仍计入排放，因此空驶占比高的线路强度会偏高。

线路两侧都有有效服务量与能耗记录时才可比较改造效果（comparable），输出强度差与降幅百分比；否则 comparable 为 false，reasons 说明原因：无柴油行程、无电动行程、行程缺少有效服务量、缺少能耗记录。fleet_electric 给出全网电动加权强度，作为没有自身电动数据线路的参考。

## 方案排序与批准复现

采购方案（plan）登记后不可变，内容为一批拟电动化的线路。排序按预计减排量：线路预计减排 =（柴油基线强度 − 电动参考强度）× 柴油侧服务量，电动参考优先取线路自身电动强度，缺失时取全网电动加权强度并标注 reference_source。缺少柴油基线或电动参考的线路从方案中排除并列明原因；预计减排量不为正的方案不会成为推荐。

批准方案时，把当时的 as_of 时点、排放假设、候选方案集合与排序结果整体存入不可变的批准记录。reproduce 用批准时的时点和假设重算，验证结论可复现；reassess 用批准时的假设和当前全部数据重估，显示新证据（中途换线补登、计费电量补录等）是否改变推荐以及已批准方案的预计减排变化。批准之后新登记的方案不在重估范围内，需要重新批准。
